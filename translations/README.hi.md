# dpdp-law-to-code

**भारत के डिजिटल पर्सनल डेटा प्रोटेक्शन अधिनियम, 2023 — चलाने योग्य Python कोड के रूप में। MIT · ₹0 · स्थानीय-प्रथम।**

भारत सरकार ने जिस ढाँचे की सार्वजनिक खोज शुरू की है, यह उसका एक नागरिक-निर्मित संदर्भ कार्यान्वयन है।

## यह क्यों मौजूद है — MeitY का संकेत

20 मई 2026 को, *Economic Times* ने रिपोर्ट की कि **इलेक्ट्रॉनिक्स और सूचना प्रौद्योगिकी मंत्रालय (Ministry of Electronics and IT — MeitY)** एक अवधारणा पर उद्योग जगत से व्यापक परामर्श कर रहा है जिसे वह **"Law-to-Code"** कहता है — यानी डिजिटल पर्सनल डेटा प्रोटेक्शन अधिनियम 2023 के प्रावधानों को मशीन-निष्पादन योग्य एल्गोरिथ्म में अनुवाद करना।

हिमांशी लोहचब और सुभायन चक्रवर्ती द्वारा लिखित लेख *"Coded Compliance: Centre is Eyeing 'Law-to-code' to AI-proof Data Law"* (Economic Times, 20 मई 2026) के अनुसार, यह परामर्श लगभग एक माह से चल रहा है और सीमांत AI मॉडलों की तीव्र प्रगति के प्रति MeitY की व्यापक प्रतिक्रिया का भाग है।

लेख से सीधा उद्धरण:

> *"Law-to-code is the practice of translating legal rules into machine-executable algorithms such as a Python code that software can automatically process and enforce without human intervention."*

> *"A 'base code' for legal provisions can ensure that systems are compliant by design without needing an army of lawyers to interpret every technical step."*

MeitY के परामर्शों में जिन व्यावहारिक अनुप्रयोगों की पहचान की गई है, उनमें शामिल हैं — सहमति के बिना व्यक्तिगत डेटा तक पहुँच के प्रयासों को रोकना, अनुमत अवधि से अधिक डेटा प्रतिधारण पर चेतावनी, स्वतः-विलोपन प्रवाह, और उत्पादन प्रणाली में अंतर्निहित डिज़ाइन-दर-अनुपालन।

**यह रिपॉज़िटरी सरकार द्वारा जनता के समक्ष रखे प्रश्न का एक नागरिक का उत्तर है।** यह कोई प्रतिस्पर्धी प्रस्ताव नहीं है, न ही आलोचना। यह एक खुले-स्रोत, चलने योग्य संदर्भ कार्यान्वयन है — इस आशा से प्रकाशित कि यह उस संवाद को आगे बढ़ाए जो भारत सरकार ने आरंभ किया है। यदि MeitY औपचारिक ढाँचा प्रकाशित करता है, यह रिपॉज़िटरी उसके अनुरूप अद्यतन की जाएगी।

## यह क्या है

DPDP अधिनियम 2023 (धारा 5–16) के परिचालन प्रावधानों को `pip install`-योग्य Python पुस्तकालय के रूप में एन्कोड किया गया है। प्रत्येक फ़ंक्शन संरचित `ComplianceResult` लौटाता है, जिसमें वैधानिक उद्धरण शामिल है।

- एक अकेला डेवलपर इसे आज दोपहर अपने codebase में जोड़ सकता है।
- एक स्टार्टअप अनुपालन टीम बिना enterprise-sales call के इसका ऑडिट कर सकती है।
- संसाधन-संपन्न बड़े विधि-संस्थान अपने स्वयं के वाणिज्यिक ढाँचे समय आने पर प्रस्तुत करेंगे। यह एक खुला, निःशुल्क, और आज उपलब्ध है।

## इसे कैसे उपयोग करें — तीन रास्ते

### रास्ता A — अपने Python codebase में (डेवलपर्स के लिए)

यदि आपकी टीम पहले से Python का उपयोग करती है, इसे किसी भी अन्य library की तरह उपयोग करें — `from dpdp.consent import check_consent` आयात करें और अपने request handler में call करें।

### रास्ता B — टर्मिनल से (अनुपालन अधिकारी, ऑडिटर)

Python जानने की आवश्यकता नहीं। केवल टर्मिनल खोलें और एक कमांड चलाएँ:

```bash
dpdp-check --section 6 --input consent.json
```

आपको वैधानिक उद्धरण सहित सादे शब्दों में निर्णय प्राप्त होगा।

### रास्ता C — AI सहायक के माध्यम से (वकील, संस्थापक, कोई भी)

यदि आप Claude, Cursor, ChatGPT, Gemini, या कोई अन्य कोड-समर्थ AI सहायक उपयोग करते हैं, तो आपको कुछ भी स्थापित करने की आवश्यकता नहीं — सहायक स्वयं library को install करके call कर सकता है।

**⚠ आवश्यक डेटा-संरक्षण सूचना — पथ C के पहले अनिवार्य पठन:**

DPDP अधिनियम 2023, **धारा 8(5)**, के अनुसार प्रत्येक Data Fiduciary से "उचित सुरक्षा उपाय" अपेक्षित हैं। निःशुल्क उपभोक्ता chatbot में वास्तविक व्यक्तिगत डेटा डालना स्वयं एक उल्लंघन हो सकता है।

**किसी भी वास्तविक उत्पादन डेटा को AI में डालने से पहले दो अनिवार्य शर्तें:**

1. **केवल पेड / वाणिज्यिक API tier का उपयोग करें — जो Data Processing Agreement (DPA) द्वारा शासित हो।** अनुशंसित endpoints:
   - **Anthropic Claude API** (पेड · Commercial Terms)
   - **OpenAI API / Codex** (पेड · Enterprise terms)
   - **Google Gemini API** (पेड · Workspace / enterprise terms)
2. **पुष्टि करें कि "training-on-input" बंद है।** निःशुल्क ChatGPT / Gemini / Claude.ai उपभोक्ता-स्तर पर इनपुट प्रशिक्षण-कार्य में उपयोग कर सकते हैं — किसी वास्तविक Data Principal की पहचान योग्य जानकारी के लिए अनुपयुक्त।

केवल **सीखने, अन्वेषण, या काल्पनिक उदाहरणों** के लिए — कोई भी tier ठीक है। **वास्तविक डेटा** के लिए — पेड API + DPA, अपवाद नहीं।
